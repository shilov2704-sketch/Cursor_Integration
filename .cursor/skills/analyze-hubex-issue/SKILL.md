# Анализ проблемы HubEx

Код продукта **не** в этом репозитории. **Сначала** код через MCP `ado` / `user-ado`: `search_code`, `repo_get_file_content`, `repo_list_directory`. Карта: `ado/code-repos.json`. MCP `hubex` — после кода, чтобы сверить живые данные; при «только анализ» данные не меняй.

Если инструментов MCP ADO **нет в этом прогоне** — остановись. Напиши, что нужен stdio MCP `ado` на [cursor.com/agents](https://cursor.com/agents) → MCP. **Не выдумывай код.** Если нет только `hubex` — код всё равно ищи через `ado`; живые данные тогда через `scripts/hubex-api.mjs`.

## Как читать тред (не перепутать кейс)

1. Выпиши условия дословно: «если…», «когда…», «при наличии…». **Не инвертируй.** Пример: «баг, если у родителя **есть** аватарка» ≠ «если аватарки нет».
2. Заголовок, шаги и фактический результат должны говорить про **одно и то же** условие.
3. Скриншоты — доказательство, не замена текста. Если на скрине родитель с фото, а в тексте «без аватарки» — перечитай тред и последнее сообщение человека; не усредняй.
4. Ищи по тем же словам в коде: аватар, photo, image, parent, child, тип объекта, default type.

## Цепочка UI → API → сервис

Не ставь платформу по тому, что на скрине веб-страница.

1. Найди экран/форму во фронте (`HubEx.Frontend.MainApp` / `AdminApp` / `HubEx.Frontend.RN.Worker`).
2. Найди, какой запрос её наполняет (ручка, DTO, поле).
3. Прочитай сервис, который отдаёт это поле (`HubEx.Service.*.Api`).
4. Платформа = **где ломается данные или контракт**, не где это нарисовали:
   - опечатка/значение в API, сид, справочник, 500, неверный JSON → `backend`
   - только вёрстка, тултип, CSS, обрезка сайдбаром → `web`
   - МП / android / ios / worker app / RN → `mobile`
   - админка без отдельного шаблона → всё равно шаблон `web` (Area `HubEx\Frontend\WebApp`), не выдумывай `AdminApp` как Area Path
5. Пока не посмотрел и фронт, и связанный API — **не выбирай** `web` «по умолчанию». После кода, если есть MCP `hubex` — сверь сущность на DEV.

Склад / WH / оприходование / Receipt → `HubEx.Service.WH.Api`. Объекты / родитель / дочерний / аватар → `HubEx.Service.ES.Api` + MainApp.

## Поиск

- `search_code`: `project: HubEx`, `top` 15–20, несколько запросов (экран, поле, ручка).
- Затем `repo_get_file_content` с `project=HubEx`, `versionType=Branch`, `version` ветки по умолчанию.
- Пустой search — `repo_list_directory` по папкам из карты.

## Если только «сделай анализ»

Это отдельная команда. **Не создавай Bug.** Не вызывай воспроизведение на DEV, не запускай Playwright/API ради карточки.

Весь разбор отдай **в ответе пользователю** (русский): проблема, репозитории, шаги, причины с путями и фрагментами, что проверить. Не сворачивай ответ до одной строки со ссылкой.

## Если это шаг перед «заведи баг»

Тот же разбор. В чат Teams разбор **не** пиши целиком — его положат комментарием к багу (см. skill `create-hubex-bug`). Перед карточкой попробуй воспроизвести кейс на DEV (skill `reproduce-hubex-dev`).
